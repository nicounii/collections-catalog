# src/data/

## Responsibility
Product catalog data source and related constants. Manages data import from generated JSON files produced by Airtable sync.

## Design Patterns
- Module-based data export
- Separation of source data (generated) from API surface (products.js)
- Fallback strategy for development without credentials
- Data normalization with consistent schema

## Key Data
- **products.generated.json**: Generated catalog from Airtable (via `scripts/sync-catalog.mjs`)
- **products.sample.json**: Fallback sample data for dev without Airtable credentials
- **products.js**: Main data module
  - Imports `generated` from `products.generated.json`
  - Exports `CATEGORIES` array (Todos, Quadrinhos, Marvel Comics, DC Comics, Novidades, Action Figures, Retro Gaming, Livros de Coleção)
  - Exports `products` array (from generated)
  - Exports `byCategory(cat)` - filters products by category
  - Exports `journalPosts` array - blog/journal content
  - Exports `NAV_LINKS` and `SUB_NAV` arrays for navigation
- Product schema (typical): `{ id, title, maker, price, image, category, description, note, lot, art, added, ... }`

## Data & Control Flow
1. `npm run sync` (or prebuild/predev) runs `scripts/sync-catalog.mjs`
2. Sync reads from Airtable if credentials present, else copies `products.sample.json` to `products.generated.json`
3. `products.js` imports from `products.generated.json`
4. Components/hooks consume via `products`, `byCategory()`, etc.
5. Catalog filters/sorts/paginates the products array

## Integration Points
- Consumed by: src/hooks/useProducts.js, Catalog.jsx, CategoryRail.jsx, App.jsx (via byCategory)
- Generated by: scripts/sync-catalog.mjs
- Depends on: products.generated.json (build artifact)
